## WebKit・アクセシビリティ・Lighthouse の確認（2026年11月1日）

### WebKit（iPhone の Safari と同じ描画エンジン）

CI に `e2e-webkit` を足した（iPhone 13 の画面の大きさ）。生徒・講師の通しテスト、画面の決まり（ui-rules）、アクセシビリティの検査、スマホ幅の見た目を流し、46件合格（1件はもともと条件付きで飛ばすもの）。手元では `E2E_WEBKIT=1 pnpm e2e`。

最初に流したとき、Chrome では出ない違いが3つ見つかり、直した。

| 見つかったこと | 直したこと |
| --- | --- |
| 閉じたアコーディオン（担当の講師）の中のリンクが、見えないのに読み上げの対象に残っていた | 閉じたら中身を `visibility: hidden` にし、閉じる動きが終わってから消す |
| 予約の確認ダイアログを開く動きの途中で、文字と背景のコントラストが足りないと判定された | ダイアログの背景色を明示した。検査は開く動きが終わってから行う |
| 「動きを減らす」設定のとき、スケルトンのシマーが止まっているかの確認が、疑似要素の計算済みスタイルの返し方の違いで判定できなかった | 設定が効いていることと、シマーのアニメーションが動いていないことを直接確かめるようにした（アプリ側は正しく止まっていた） |
| 2回目に流したとき、予約の枠を選んだ直後の色の切り替えの途中を測り、コントラスト不足と判定することがあった | 画面の決まりの確認も、色の切り替えの動きが終わってから測る（テストの直し） |

## 仕上げの見直し（v1.19）で直したこと

公開前の最後の見直しで、次の不具合を見つけて直した。どれもテストを先に書いて、失敗することを確かめてから直した。

| 重さ | 内容 | テスト |
| --- | --- | --- |
| 中 | 繰り返し予約（RS-07）の期間に上限がなく、終わりの日の打ち間違い（100年先など）で何千件も作ろうとした。終わりが始まりより前・始まりが今日より前の期間も受け付けていた | `RS-07 繰り返し予約の期間は、終わりが始まりより後で、今日以降、設定の週数まで` |
| 中 | 入力の誤りの文言が英語のまま画面に出ることがあった（「Too big: expected string…」など） | `UI-16 入力の誤りは、英語や内部の型の名前を出さず、日本語で返す` |
| 小 | URL の ID の形が正しくないと「エラーが発生しました」（500）になった。今は「見つからない」（404） | `5.2 形の正しくない ID は「見つからない」（404）にし、内部のエラーにしない` |
| 小 | 繰り返し予約で、想定外のエラーの中身（データベースの文言）を予約できなかった理由として画面に出していた | 同上の RS-07 の修正に含む |
| 小 | 操作記録（OP-03）が内部の名前（`package.create` など）と JSON のまま表示されていた | `OP-03 操作記録は、操作の名前・操作した人・対象の名前・内容を、内部の記号を出さずに返す`、`OP-03 コードで記録しているすべての操作に、日本語の名前がある` |
| 小 | Excel で保存した Shift_JIS の CSV が文字化けし、見出しの誤りとして断られた | `ST-01 Excel で保存した Shift_JIS の CSV も、文字化けせずに読み込める` |

あわせて、画面の決まりの自動チェックに「スマホの幅（390px）でページが横にはみ出さない」を足し、全画面で合格した。

## 初版の確認の途中で直したこと

アプリの不具合は見つからなかった。テストの書き方に誤りが4つあり、直した。

1. ログインの補助関数が、ログインの完了を待っていなかった。そのため一部の「画面の決まり」の確認が、ログイン画面を測っていた。直したうえで、全画面で測り直して合格した
2. 入力欄の文字の大きさ（UI-03）の確認に、チェックボックスまで含めていた。iPhone で拡大が起きるのは文字を入力する欄だけなので、対象を絞った
3. 開発用サーバーで、Cookie のホスト名（localhost と 127.0.0.1）が食い違っていた
4. 画面が切り替わる前に入力欄を探していて、たまに失敗していた。切り替わりを待つようにし、全体を2回続けて流して2回とも合格した
